# LaTeX 写作与编辑规则

## 源文件优先与最小修改

- 当前用户指令和当前源文件优先于本引用文件。
- 保留现有记号、标签、编号、术语和结构。
- 当前符号有效但另一种选择可能更合适时，先提出并解释改符号的建议，再实施改动。

## 中文科技排版

- 在中文 LaTeX 行文中，使用半角逗号并在其后加空格：`, `。
- 中文句末使用半角句号并在其后加空格：`. `。
- 使用半角冒号并在其后加空格：`: `。
- 中文引用或强调使用中文全角双引号：“……”。
- 中文引用不要使用 LaTeX 英文引号形式 ``...''。
- 源文件中，中文与相邻英文词、数字或行内数学之间保留一个半角空格。
- 公式外的解释性中文使用半角圆括号，并按句子需要保留周围空格。

## 对话与 LaTeX 源码中的公式

- 在普通对话正文中，行内数学使用 `\(...\)`，单独展示公式使用 `\[...\]`；不要用 `$...$` 作为对话公式定界符。
- 在交付给用户的 LaTeX 源码中（包括围栏代码块和 `.tex` 文件），行内数学默认使用 `$...$`；单独占一行的展示公式使用 `\[...\]`。当前源文件已有不同的明确约定，或用户另有要求时，以其为准。
- 有助于可读性时，将短公式保留在行内；不要随意拆成展示公式。
- 用户将要粘贴进文档的 LaTeX 放入围栏代码块，或以 `.tex` 文件交付。

## 交叉引用

- 编辑已有文档时，默认保留原有交叉引用写法，不自动统一或替换现有引用命令。
- 涉及交叉引用且文档尚未加载 `cleveref` 时，先说明用途和需要加入导言区的精确命令，询问用户是否引入；得到明确同意前沿用现有写法，不写入依赖该宏包的命令。同一文档中用户已作出决定时，不重复询问，除非需求发生变化。
- 以下 `cleveref` 专用写法适用于文档已采用该宏包或用户已同意引入的情形：句中使用 `\cref{...}`，句首使用 `\Cref{...}`；引入时在授权范围内配套调整宏包、名称配置和相关引用。
- 让 `cleveref` 自动生成图、表、定理、引理、推论、定义、算法、公式和节等对象名称；不要在引用命令前手动添加对象名称，也不要写成 `图~\cref{...}` 或 `Theorem~\cref{...}`。
- 同时引用多个标签时使用 `\cref{label-1,label-2,...}`；明确引用一个连续范围时使用 `\crefrange{first-label}{last-label}`。
- 中文文档根据实际计数器，通过 `\crefname` 和 `\Crefname` 显式配置所需的中文对象名称；不要假定 `cleveref` 会自动提供正确的中文名称。
- 英文文档使用与模板或目标期刊一致的英文对象名称；句首形式由 `\Cref` 处理，不手动拼接对象名称。
- 新建 LaTeX 文档时默认采用 `cleveref`；若同时使用 `hyperref`，在其之后加载 `cleveref`。编辑已有文档时，遵守上述保留原写法和先询问的规则，未经用户明确同意不直接修改导言区。
- 保留现有 `\label{...}` 的键和值，并根据标签对应的实际计数器检查 `\cref` 输出的对象名称是否正确。
- 普通对话中，将 `\cref{...}`、`\Cref{...}`、`\crefrange{...}{...}` 和标签显示为行内代码，确保反斜杠和下划线安全呈现。
- 在同一文档中保持交叉引用命令、对象名称和格式一致。

## 算法伪代码

- `\Require` 和 `\Ensure` 的说明以半角句号结束。
- 可执行的 `\State` 和 `\Return` 语句以半角分号结束。
- 中文返回消息使用中文全角引号。
- 使用 `algorithmicx` 或 `algpseudocode` 时沿用同一约定。

## `cases` 环境

- 除最后一行外，每个分支行都以半角逗号 `,` 结束。
- 若整个 `cases` 表达式结束一个完整句子，最后一行以半角句号 `.` 结束。
- 若表达式后接“其中”“则”“从而”等行文，最后一行以半角逗号 `,` 结束。
- 标点服从 `cases` 表达式在整句话中的语法作用，不机械套用模板。

### 示例

当 `cases` 表达式结束句子时，非最后分支的半角逗号写在换行命令 `\\` 之前：

```latex
\[
f(x)=
\begin{cases}
0, & x<0,\\
1, & x\ge 0.
\end{cases}
\]
```

若公式后接“其中”等文字，将最后一行的半角句号 `.` 改为半角逗号 `,`。

## 按需版面检查

- 根据改动对版面的实际影响决定是否检查，不对每次编辑机械地编译或渲染。仅改措辞、错字、注释或标签键，且没有明显的长度或布局变化时，做必要的源码检查即可。
- 新建完整可编译文档或图形、修改公式或表格的布局、浮动体、分页、栏宽、字体尺寸、TikZ 几何或标签布局，或出现溢出、遮挡、裁切等具体迹象时，若已有合适环境，进行针对性的编译和可视检查；用户明确要求检查版面时也执行。
- 优先复用项目已有编译方式，仅查看受影响的页面、图形或局部及必要的相邻页面。只有改动会传播到全篇布局时才扩大检查范围；检查通过后，没有新改动或异常不重复检查。
- 范围内、低开销的必要检查无需每次询问。若需要安装工具、联网获取依赖、显著耗时的大规模编译，或当前条件只能进行高开销的全篇检查，先说明必要性与预计范围并征求用户同意；用户已明确授权该项检查时不重复询问。
- 环境不可用或用户要求跳过检查时，明确说明未进行编译或可视检查；区分“源码已检查”“已编译”和“已查看版面”，不得将编译成功等同于版面正确。

## 导言区与文件范围

- 除非用户明确要求修改导言区，否则不要改动 `\begin{document}` 之前的任何内容。
- 将文档类、宏包、页面设置、定理环境、自定义命令、开头元信息、标题和作者均视为导言区的一部分。
- 对范围狭窄的编辑，不改标题、作者、电子邮箱、注释、宏包、参考文献样式或文件结构。
- 未要求修改导言区而需要返回完整修订正文时，仅提供从 `\begin{document}` 到 `\end{document}` 的内容。
- 若必须修改导言区，明确说明，并列出需要添加、删除或替换的精确行。
- 若围栏代码复制出现问题，提供纯文本或 `.tex` 文件；不要声称界面总会移除围栏。
