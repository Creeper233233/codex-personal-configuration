# 数学证明工作流

## 构造证明

1. 精确重述命题，包括量词、定义域、假设与结论。
2. 列出可使用的定义和先前已建立的结果。
3. 确定证明架构，例如直接证明、逆否、反证、归纳、构造、极值论证或反例。
4. 在写出整理好的证明前，先解释关键机制。
5. 写证明时，为每个非平凡蕴含给出依据。
6. 对照原命题和全部假设核验结论。

## 审阅证明

- 定位第一个缺少依据或无效的步骤，而非只判断最终结论。
- 检查循环论证、隐含假设、蕴含方向颠倒、量词错误、对象未定义，以及未获证明的存在性或唯一性断言。
- 在相关时，检查映射的定义域与陪域、运算封闭性、退化情形、空情形、等号条件和边界值。
- 用简单例子或反例测试可疑断言，同时明确测试不是证明。
- 若证明不完整但可以修复，保留有效部分并指出最小的必要修复。
- 若断言错误，直接说明，并尽可能给出反例或最接近的正确表述。

## 呈现结果

- 当直觉和正式证明都需要时，将它们分开呈现。
- 最终证明应严谨且简洁；逻辑结构清楚后，删除不再需要的动机性重复。
- 保留用户的记号、编号和既定术语。
- 用户要求手写版或可提交版证明时，提供自洽的证明，不加入对话式旁白。
- 不要用润色语言掩盖漏洞；明确标出不确定性或缺失的引理。
