# 数学学习与证明

## 核心约束

- 将当前用户请求和当前材料视为最高优先级；若其与本 Skill 冲突，以当前请求和材料为准。
- 除非用户在当前任务中提供相关背景，否则不要从过往论文、课程或计算项目中带入假设、术语、进度或结论。
- 回答前，先将任务区分为概念学习、解题、推导、构造证明、反例构造或审阅证明。
- 每次学习或讲解任务都读取 `references/learning-style.md`。
- 只要涉及证明、推导、反例或证明审阅，就读取 `references/proof-workflow.md`。
- 除非用户记号不一致或在数学上无效，否则保留用户的记号；提出改记号前，先解释原因。

## 工作流程

1. 确定起点：辨认已定义的内容、用户应当已知的内容和精确目标。
2. 按依赖顺序引入定义与符号。不得把未定义的符号、未证明的断言或未介绍的定理作为隐含前提。
3. 在压缩成形式化记号前，先解释背后的几何、代数、组合或分析机制。
4. 以小而有依据的步骤展开论证，并说明每一步为何成立。
5. 给出结论前，检查假设、量词、定义域、边界情形和可能的反例。
6. 匹配用户需要的模式：学习时提供引导式讲解，提交时提供简洁严格的解答，审阅时提供诊断报告。

## 与写作任务协同

- 若任务还要求学术表述、翻译或 LaTeX 排版，同时使用 `edit-academic-writing`。
- 数学正确性由本 Skill 负责；语言和排版决策由 `edit-academic-writing` 负责。

## 规范维护

- 当用户明确表达“以后”“默认”“统一”“始终”等长期、跨项目适用的数学学习、概念讲解、解题或证明偏好，或同一偏好反复出现时，主动提醒该要求可能适合加入本 Skill，并说明建议修改的文件和理由。
- 不把一次性要求、特定课程、单道题目或项目专属规则建议为全局规范。
- 只判断数学学习和证明范围内的规范；若同时使用 `edit-academic-writing`，不要重复提醒其负责的写作、翻译或 LaTeX 偏好。
- 未经用户明确同意，不修改本 Skill 或其引用文件。

## 引用文件说明

- `references/proof-workflow.md`：证明构造、证明审阅、严谨性检查与最终证明呈现。
