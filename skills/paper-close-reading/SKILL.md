# 论文精读与审阅

## 核心目标

按照论文原文顺序，带用户逐步阅读论文。每一段都尽量保留原文的信息、符号和论证关系，同时解释必要概念，并在对应位置检查数学或逻辑问题。

本 Skill 适用于数学、理论计算机科学以及包含定义、定理、算法和证明的学术论文。它既服务于论文学习，也服务于逐步审稿。

## 核心约束

- 确认具体要阅读的论文和范围。除非用户明确扩大范围，只阅读指定论文。
- 在用户指定范围内按原文顺序推进，不擅自跳过重要段落；核对依赖的定义、引理或附录证明时可临时跳转，之后返回原位置。
- 区分逐步学习与完整范围审阅：逐步学习按检查点推进；用户要求完整审阅指定章节或全文时，完成该范围后统一报告，不因默认的小段检查点反复等待确认。
- 用户要求“继续”时，从上一次明确的阅读位置继续；用户指出讲快、跳步或符号未定义时，立即退回最后一个未解释清楚的位置。
- 不把一次性的论文结论、审稿意见或项目文件内容写入本 Skill；它们属于具体项目记录。
- 论文原文、解释、审稿判断和建议修补必须明确区分。

## 阅读流程

1. **确定起点和范围**：根据当前请求确定论文文件、目标章节、用户已经理解的内容，以及逐步学习或完整范围审阅模式；已有信息足够时直接开始。
2. **按原文分段**：逐段阅读当前内容。若正文引用了附录证明，先在需要的位置阅读对应证明，再回到正文原顺序。
3. **按需翻译**：精读外语论文或用户要求翻译时，逐段提供忠实译文，默认译为中文，保留公式、定义、量词、编号、引用、逻辑强度和作者的限定条件；中文论文直接解释，完整范围审阅不默认附上全文翻译。
4. **解释原文**：逐步学习时，在相应原文或译文之后单独说明术语、对象、动机、几何或组合机制，以及每一步改变和保持的内容；完整范围审阅时按问题需要提供解释。
5. **检查论证**：核对对象、定义域、假设、推理步骤、边界情况和定理适用条件；涉及优化或算法时，再核对可行域、目标函数、额外约束和复杂度。
6. **记录问题**：在问题第一次出现的位置指出错误、歧义、未证明步骤或记号问题；区分“结论错误”“证明缺口”“可以修补的表述问题”和“仅是风格问题”。
7. **报告进度或结果**：逐步学习时，每次推进一个小的连贯段落或一节较短内容，明确下一次的原文位置并等待用户继续；完整范围审阅时，完成指定范围后统一报告发现和实际覆盖范围，说明因材料缺失等原因未能核验的部分。

## 翻译和讲解规则

- 用户要求精读外语论文且未排除翻译时，翻译本次阅读范围内的主要段落，不能只挑核心结论概括；中文论文不重复翻译成中文，用户另有目标语言时按其要求。
- 数学公式、符号、定理编号和参考文献编号保持不变。对话中的行内公式使用 `\(...\)`，独立公式使用 `\[...\]`。
- 新出现的符号、术语和定义先简要介绍再使用；当前对话中已经建立、或用户明确允许使用的结果可以直接引用。新用到的定理或工具先说明内容及适用条件，是否展开证明由当前目标决定，不得暗用未说明的假设或尚未证实的断言。
- 抽象定义应配合一个直接例子；必要时也给出反例或边界情形。
- 区分直觉解释与严格证明。对于每个非平凡不等式或构造，说明为什么成立。
- 明确区分数学对象本身和它的记号，尤其区分：最优解、证明中构造的比较解、算法实际输出和任意可行解。
- 对不同问题变体先分别定义，再比较可行域、目标函数、限制条件和算法保证；不要因为名称相似而默认它们等价。

## 原文图片的同步展示

- 讲解到原文图片所在的内容，或正文引用该图并需要结合图片理解时，在同一条回复的相应讲解位置直接展示原图，方便用户对照学习；不等待用户另行要求，也不只给出图号、链接或文字描述。
- 优先使用当前论文版本中的原图；对于 PDF，可渲染对应页面并裁剪图片区域，保留理解所需的子图、图例、坐标、标注和图注。展示时注明原图编号与页码，按需翻译图注，并结合正文解释图中对象及其对应关系。
- 图片应清晰可读；细节较多时可补充局部放大图。无法可靠提取时，展示可用的原文页面截图；仍无法展示或辨认时，明确说明限制，不以猜测或自行重绘的图片冒充原图。补充绘制的示意图须明确标注为讲解辅助图。

## 数学证明与审稿规则

- 首先定位第一个缺少依据或不成立的步骤，而不是只评价最终定理。
- 检查量词、定义域、假设、推理方向、等号情况和退化情形；涉及优化时，进一步核对可行域、目标函数和额外约束。
- 核对引用引理中的对象和假设是否与当前问题匹配；涉及不同模型时，逐项比较可行域、目标函数及限制条件，不因名称相似而互换结论。
- 发现证明不完整但结论可能成立时，明确写成“证明缺口”。能确认修补有效时给出最小修补，并标注为审阅者的补充；不能确认时，说明缺失的论证、所需条件及尚未解决的部分，不强行补证。
- 只有具有充分数学依据时，才判断陈述本身为“结论错误”；依据可以是反例，也可以是严格论证其否定、推出矛盾或其他有效反驳。仅发现原证明有缺口，不足以判定结论错误。
- 仅在论文涉及树、换边等结构操作时，检查相关的连通性、无环性、顶点或度数限制及其他实际要求。
- 复杂度说明要区分算法实际执行的步骤、证明中只用于比较的构造，以及输入参数是否固定。

## 追问处理

用户询问某个词、符号、引理或证明步骤时：

1. 回到原文中的确切句子或公式；
2. 先解释对象的定义，再解释它在当前证明中的作用；
3. 给出一个小例子或图结构描述；
4. 指出它与相近概念的区别；
5. 如有问题，说明是原文错误、证明遗漏、定义歧义还是我的补充解释。

对“存在”“任意”“至少”“至多”“最优”等词，明确说明量词范围。涉及算法或优化问题时，明确区分算法输出、最优解、比较对象和任意可行解。

## 原文定位与读取不确定性

- 首次阅读时标明使用的论文版本或文件标识；版本无法确定时如实说明。续读或更换文件时核对来源，避免混用不同版本。
- 讲解、审阅意见及阅读检查点提供足以复查的位置：按材料可用信息给出页码、节号、定理或公式号，必要时补充段落起始语；PDF 页序与正文印刷页码不一致时注明所用编号。
- 截图模糊、公式识别不清或材料缺页时，明确指出不确定的位置与符号，优先核对当前可用的原图或源文件；无法确认时请求相关清晰材料，不猜补原文或基于未确认内容下定论。可继续核验不受影响的部分。

## 项目记录

对于需要多轮阅读或审稿的项目，使用 `planning-with-files` Skill，并维护：

- `task_plan.md`：目标、阶段、当前阅读位置和下一步；
- `findings.md`：论文内容、解释依据和研究发现；
- `progress.md`：每轮阅读进度、验证结果和遇到的错误；
- `review_issues.md`：按编号记录审稿问题、证据、严重程度和可行修补。

若用户要求英文规范格式，以上记录使用标准英文 Markdown；论文讲解仍按用户偏好使用中文。除非用户明确要求，保持论文原文件不变。

## 与其他 Skill 协同

- 涉及数学概念、推导、证明、反例或证明审阅时，同时使用 `guide-math-learning`；数学正确性由该 Skill 负责。
- 涉及学术翻译、术语一致性、论文语言或 LaTeX 时，同时使用 `edit-academic-writing`；语言和排版由该 Skill 负责。
- 涉及 PDF 读取、渲染或版面核验时，使用 `pdf` Skill。
- 对长篇、多轮、需要持久进度的论文任务，使用 `planning-with-files` Skill。
